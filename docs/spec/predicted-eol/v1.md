# Predicted end of life v1

A prediction estimates end of life for a component version or release line
whose end date its maintainer has yet to announce. Offing consumes verified
model evidence from Ebb. Forecast readers can display that evidence separately
from announced lifecycle events.

## Forecast v1

In [Forecast v1](https://velella.sh/offing/schemas/forecast.v1.schema.json),
`predictions` is an optional, nonempty top-level array. Omit it when model
evidence is unavailable or there are no applicable predictions. Announced
events stay in `groups` and `buckets`. The existing totals and affecting
counts cover those events only.

| Field | Meaning |
| --- | --- |
| `purl` | Canonical, versioned Package URL of the component or release line being modeled. |
| `date` | Modeled point estimate as a UTC calendar date in `YYYY-MM-DD` form. |
| `interval.earliest`, `interval.latest` | Inclusive UTC calendar dates. The interval contains `date`, including when all three values are equal. |
| `confidence` | Number from 0 through 1 inclusive, with higher values expressing greater confidence in the model output. Preserve the model's value. |
| `method` | Nonblank name or description of the model's estimation method. |
| `sources` | Nonempty array of absolute HTTPS evidence URLs used for the estimate. |
| `modelVersion` | Nonblank identifier of the model version that produced the estimate. |

Predictions are advisory by default. Existing severity gates use announced
lifecycle evidence. If a separately specified policy opts into prediction
gating, it must name a minimum confidence. When an authoritative announcement
becomes available for the same version or line, include the announcement in
the confirmed lifecycle representation and omit the superseded prediction.

## SARIF, CycloneDX and SPDX

The following extension locations describe the interchange design. The [release gate](../release-gate/v1.md) can read explicitly labeled CycloneDX and SPDX 2.3 annotations and report advisory warnings. Existing [SARIF](https://velella.sh/offing/spec/sarif/v1/) and
[SBOM](https://velella.sh/offing/spec/lifecycle-properties/v1/) profile fields
retain their announced-date meaning.

| Format | Extension location |
| --- | --- |
| SARIF 2.1.0 | Put the array in `runs[].properties.offingPredictedEol`. The existing `offingLifecycle.endOfLifeDate` keeps its confirmed-date meaning. An estimate alone creates no scan SARIF result or severity. Release gate SARIF records its advisory warnings in the release decision. |
| CycloneDX | Add one component property named `offing:lifecycle:predictedEol:v1` per applicable prediction. Its string value contains the JSON prediction object. The official lifecycle milestone properties remain for confirmed events. |
| SPDX 2.3 JSON | Add a package annotation with `annotator: "Tool: offing"` and `annotationType: "OTHER"`. Its comment starts with `offing:predicted-eol:v1:` and contains the JSON prediction object after the prefix. Use the annotation's actual creation time for `annotationDate`. |
| SPDX 3.0.1 JSON-LD | Add a Core Annotation for the package ID with `annotationType: "other"`, `contentType: "application/json"` and `comment: "offing:predicted-eol:v1"`. Its `statement` is the string-encoded JSON prediction object. Use the annotation's actual creation time in its creation information. |

The Forecast schema and checker cover the prediction object and interval.
The interchange extensions above have separate producer and conformance work.

## Conformance

Download the [checker](https://velella.sh/offing/spec/predicted-eol/conformance/check.mjs),
the Forecast schema and the
[valid](https://velella.sh/offing/spec/predicted-eol/conformance/forecast-valid.json) and
[invalid](https://velella.sh/offing/spec/predicted-eol/conformance/forecast-invalid.json) vectors. With Node.js 22 or newer
and Ajv 8 installed alongside the checker, run these commands from that directory.
Validation uses local files and leaves the evidence URLs unopened.

```sh
node check.mjs forecast-valid.json forecast.v1.schema.json
node check.mjs forecast-invalid.json forecast.v1.schema.json
```

The valid vector exits 0 and the invalid vector exits nonzero. The fixtures use
illustrative values to verify the format.
