# Agent Guard protocol v1

A caller sends a check before adding a dependency or writing a file. The
guard returns a lifecycle decision supported by the data it consulted. A
caller can implement the protocol independently of Offing and use it with
any transport.

## Request

Send a JSON object with `schemaVersion` set to `offing.agent-guard.request.v1`
and exactly one of `purl` or `snippet`.

| Field | Type | Meaning |
| --- | --- | --- |
| `purl` | string | A [Package URL](https://github.com/package-url/purl-spec). Include the intended version in the PURL when known. |
| `snippet` | object | The intended file with `path` and `content`. The path is repository-relative, uses forward slashes, and has no `..` segment. Content is the exact UTF-8 text to check. |
| `language` | optional string | A language hint for a snippet, such as `javascript` or `python`. The path still supplies file and manifest context. Omit the hint for dependency checks. |
| `context` | optional object | Per-request policy. Its optional `failOn` is one of `info`, `low`, `medium`, `high`, `critical`, or `none`. The default is `high`. |

The guard treats the supplied text as data. A request authorizes a check of
its explicit subject. It grants no permission to execute code, perform an
install or edit, or inspect other files.

```json
{
  "schemaVersion": "offing.agent-guard.request.v1",
  "purl": "pkg:npm/request@2.88.2",
  "context": { "failOn": "high" }
}
```

```json
{
  "schemaVersion": "offing.agent-guard.request.v1",
  "snippet": { "path": "src/client.js", "content": "export const endpoint = '/api';\n" },
  "language": "javascript"
}
```

## Response

Return a JSON object with `schemaVersion` set to
`offing.agent-guard.response.v1`, a `decision`, and a non-empty `reason`
that explains the result in terms of the subject and any applicable policy.

| Decision | Host behavior | When to return it |
| --- | --- | --- |
| `allow` | May proceed. | The check completed with no applicable finding and enough data to make that determination for the checked subject. |
| `warn` | May proceed after surfacing the reason. | A finding is below the configured threshold or blocking is disabled, or the guard lacks the version or lifecycle data needed to decide. |
| `block` | Must stop the proposed operation. | An applicable finding meets or exceeds the configured threshold. |

Severities increase in the same order as in the request table. When findings
have different severities, use the highest to determine the decision. For an
unversioned dependency, a rule applying to every version can still produce a
finding. If only some versions are affected, ask for the intended version
in the warning reason. For an allowed snippet, limit the reason to what the
check covered.

When known, include a `replacement` string naming the recommended alternative
and a `source` string containing an absolute HTTP or HTTPS URL for the
underlying evidence. If both are present, the source must support the reason,
and the replacement must address that same finding. Omit unavailable fields.
A missing rule or source supplies no evidence of safety. Invalid requests and
failed checks are errors reported by the transport. They do not carry an
`allow`, `warn`, or `block` decision.

```json
{
  "schemaVersion": "offing.agent-guard.response.v1",
  "decision": "block",
  "reason": "request is deprecated and meets the high severity threshold.",
  "replacement": "Native fetch or a maintained HTTP client",
  "source": "https://www.npmjs.com/package/request"
}
```

## Existing Offing entry points

The protocol above specifies the shared payload. Offing currently exposes
package and snippet checks through [`check_dependency` and `check_snippet`
in MCP](../../MCP.md#tools), and through [`offing check` and `offing
check-snippet`](../../CLI.md#check-snippet) in the CLI. Those checks return
their versioned findings. [Install guard](../../guard.md) already applies its
own severity gate before running the package manager.
