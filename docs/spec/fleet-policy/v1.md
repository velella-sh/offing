# Fleet policy v1

The [fleet policy schema](https://velella.sh/offing/schemas/fleet-policy.v1.schema.json) defines an organization document. Use `schemaVersion: "offing.fleet-policy.v1"` and a `policy` object with `rules` and optional `exceptions`. A repository selects the document with `extends` in `.offing.json`. Its existing `policy` becomes the repository layer. `offing scan --policy <reference>` or the Action `policy` input selects the organization document explicitly.

## Resolution

A relative `extends` resolves from `.offing.json` and stays inside the repository. A GitHub reference is `github:org/repo[/path][@ref]`. A GitLab reference is `gitlab:group/project[@ref]`, including nested groups. The default source is `.offing-policy.json` at the default branch head. An explicit full commit selects only that commit.

`offing policy pull` resolves a remote ref to a commit and validates the document before saving its snapshot. `offing scan --policy-online` opts into the same refresh. Regular scans and the Action read local policies or an existing snapshot from Offing's user cache. An unavailable pin fails validation. Requests take fixed GitHub or GitLab API routes and pin file reads to the resolved commit.

## Inheritance

Apply organization rules, then one team, then repository rules. Each layer can add a rule ID. Matching IDs merge fields, and unspecified fields stay inherited. Repeated rule IDs within a layer fail.

An organization document can declare `teams` as a map from slug to team policy and optional `repositories` names. An explicit repository match wins. Otherwise, the owners of the repository root from the first available CODEOWNERS file are matched by team slug. Multiple matching teams are ambiguous and fail.

The organization can delegate specific keys with `allowLoosen`. Changes outside that list have the following rules.

| Key | Allowed tightening |
| --- | --- |
| `days-left` | Increase an existing threshold |
| `severity` | Lower an existing minimum severity |
| `after-eol` | Keep the existing value |
| `path`, `ecosystem` | Keep the existing selector |
| `exceptions` | Keep inherited exceptions. Lower layers need explicit permission to append an exception. |

Adding a condition to an inherited rule narrows the set of matching findings. It needs delegation for that key. Rejected overrides report the file and line of the attempted change and the existing rule. `offing policy explain <rule>` shows the winning layer and source of each field.

Each exception requires a path or ecosystem scope, an owner, a reason and a UTC expiry date. It is valid through the expiry day. An expired exception fails validation before the policy is evaluated.

## Conformance

Download [check.mjs](https://velella.sh/offing/spec/fleet-policy/conformance/check.mjs) and [vectors.json](https://velella.sh/offing/spec/fleet-policy/conformance/vectors.json) into the same directory. Run `node check.mjs offing` using a Node.js 22 or newer. An independent implementation can supply any command that exposes the documented validate and explain interface. The script uses temporary files and no network.
