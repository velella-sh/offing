# Campaign v1

The campaign file accepts strict JSON or YAML without aliases. The schema is
[offing.campaign.v1](https://velella.sh/offing/schemas/campaign.v1.schema.json).
Use a stable lowercase `id` and an explicit ISO calendar date in `asOf`.

## Select repositories

Give exactly one selector in `select`.

| Selector | Required evidence |
| --- | --- |
| `ruleId` | An exact rule ID in the pinned Fleet forecast observations for `asOf`. |
| `release: { product, line }` | A concrete runtime pin for the product from `fleet --campaign-input` for `asOf`. A major line such as `18` matches `18.x.y`. A minor line such as `3.10` matches `3.10.x`. |
| `upgradeTarget: { runtime, version }` | An explicit `ready` result for the same runtime, version, pin and date. Failed, blocked, unknown and missing evidence appear in omissions. |

Include and exclude lists contain exact names such as `team/service` or fully
qualified repository identities such as `https://github.com/team/service`.
Exclusion takes precedence. An omitted or empty include list permits all
matching repositories. Selection needs a scanned or cached row with a commit
SHA and the selector's corresponding evidence. A list entry cannot establish
selection by itself.

`target` is an optional intended runtime and version when selecting by a rule
or current release line. With `upgradeTarget`, the selector supplies the
target and a separately supplied target must agree. A target never changes
what the pinned capture observed.

## Plan and state

`batching` contains positive `size` and `concurrency`, nonnegative
`minGapMinutes`, and a `maxFailureRate` fraction from zero to one. Concurrency
must be at most the batch size. Planning assigns consecutive repositories
to batches of the requested size. The nearest recorded deadline of any
selected owner sets the priority, falling back to the repository's own
nearest dated observation. Dates sort earliest first. Repositories without
dates sort last, and the host and full name break ties.

The planner lists codemod IDs that produced patches on the pinned tree and
setup, install, build and test commands detected from its files. This is
repository-wide evidence. Review whether a patch advances the chosen target.
A JSON `null` means no corresponding observation was recorded. An empty
array means an observation was recorded and produced zero entries. Report
only the commands the detector identified on the recording machine.

The output conforms to
[offing.campaign-state.v1](https://velella.sh/offing/schemas/campaign-state.v1.schema.json).
It repeats the campaign identity, day, batching and optional intended target.
Every repository has a unique host and name, immutable commit SHA, batch,
current status and ordered transition history. Omitted repositories have one
reason. Initial plans contain `queued` states and empty histories. State
readers validate all history entries and do not make transitions.

| Status | Next statuses |
| --- | --- |
| `queued` | `running`, `cancelled` |
| `running` | `verified`, `failed`, `cancelled` |
| `verified` | `review`, `failed`, `cancelled` |
| `review` | `merged`, `closed` |
| `failed` | `queued`, `cancelled` |
| `closed` | `queued` |
| `merged`, `cancelled` | Terminal |

History begins at `queued`, is contiguous, and ends at the recorded status.
Each entry names its `from` and `to` statuses and a UTC timestamp `at` in
JavaScript ISO format with milliseconds. Timestamps cannot go backwards. `review` represents a
repository awaiting review after publishing a pull or merge request. These
statuses define interoperable state. The current CLI produces the plan and
reads state without executing the batch settings, checks or migrations.
When MCP shortens a response, its `more` pointer leads to the complete
file through `offing campaign status <file> --json`.

## Standalone checker

Copy [check.mjs](conformance/check.mjs), the two published schema files and the
example [campaign](conformance/valid-campaign.json) and
[state](conformance/valid-state.json) to a clean directory. Install Ajv 8 and
YAML 2 next to the checker, or use the copies and dependencies in an installed
`@velella/offing` package.

```sh
node check.mjs valid-campaign.json valid-state.json schemas
```

The [invalid campaign](conformance/invalid-campaign.json) and
[invalid state](conformance/invalid-state.json) exercise a nonexistent
calendar date and a forbidden transition. Run each alongside the valid
document of the other kind.
