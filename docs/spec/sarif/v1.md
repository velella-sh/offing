# Offing lifecycle SARIF profile v1

This profile carries evidence-backed software lifecycle findings in SARIF 2.1.0.
A conforming log satisfies the base SARIF format and the requirements below.
Tools can implement this profile independently of Offing.

## Rules and results

A lifecycle run declares its rules in `tool.driver.rules` and its findings in
`results`. A run with no findings may have empty arrays. A log can contain more
than one run.

- Rule IDs are unique within each run. Use a stable, producer-namespaced ID
  with lowercase ASCII letters and digits in segments separated by dots or
  hyphens, such as `github-actions.checkout.node20`. Keep that ID when the
  rule's wording or evidence changes.
- Each result has a `ruleId` and a zero-based `ruleIndex` that refer to the
  same rule in that run. It has a non-empty `message.text` and a physical
  location with a repository-relative artifact URI. Use forward slashes and
  include a one-based `region.startLine` when known.
- Each result has a non-empty `partialFingerprints["offingFindingId/v1"]`.
  Keep it stable when wording, evidence, severity, or the data release changes.
  Downstream systems can use the fingerprint to match repeat scans.

## Lifecycle properties

Each rule descriptor and each result carries an `offingLifecycle` object in
its SARIF `properties` bag. Other properties in the bag may accompany it.
The fields describe the rule at its default severity or the specific finding
at its actual severity.

| Field | Type | Meaning |
| --- | --- | --- |
| `severity` | required string | One of `critical`, `high`, `medium`, `low`, or `info`. |
| `endOfLifeDate` | optional string | Known lifecycle deadline as a valid Gregorian calendar date in `YYYY-MM-DD` form. |
| `source` | optional string | Absolute HTTP or HTTPS URL for the primary evidence, when available. |
| `replacement` | optional string | Non-blank description of the replacement or upgrade, when known. |

Omit unavailable optional properties. The profile allows only the fields in
the table inside `offingLifecycle`. Additional evidence and migration details
can appear in SARIF rule help. When `helpUri` and a rule's `source` are both
present, use the same URL for each.

The rule's `defaultConfiguration.level` and the result's `level` match their
respective lifecycle severities. A result may differ from its rule's default.

| Lifecycle severity | SARIF level |
| --- | --- |
| `critical`, `high` | `error` |
| `medium` | `warning` |
| `low`, `info` | `note` |

Offing writes SARIF with `offing scan . --format sarif`. Use a release whose
SARIF output implements this profile. Earlier releases can emit base SARIF
without the lifecycle properties.
