# Lifecycle properties v1

This profile records a dated lifecycle rule that applies to a component's Package URL and version. Offing uses the offline [Ebb registry v2 schema](https://github.com/velella-sh/ebb/blob/v0.2.0/schemas/registry.v2.schema.json) to interpret the component's PURL, affected VERS range and evidence. When an explicit version appears in the PURL, it takes precedence over the version in the SBOM. Symbols and rules whose applicability depends on an unknown version produce no milestone.

## Mapping

| Ebb field or event | Meaning | CycloneDX property or reference |
| --- | --- | --- |
| `end-of-support` and `deadline` | End of vendor support, as a UTC calendar date `YYYY-MM-DD` | `cdx:lifecycle:milestone:endOfSupport` |
| `end-of-life` or `scheduled-end-of-life` and `deadline` | Observed or scheduled end of life, as a UTC calendar date `YYYY-MM-DD` | `cdx:lifecycle:milestone:endOfLife` |
| `id` | Nonempty, stable rule identifier | `offing:lifecycle:ruleId` |
| `sources[].url` | One HTTPS evidence URL per source | `offing:lifecycle:source` and a component-level external reference to the URL |
| `replacement` | Optional nonempty producer-supplied replacement text | `offing:lifecycle:replacement` |

CycloneDX properties use string values. The official milestone names and their broader ISO 8601 date or timestamp syntax are defined in the [CycloneDX lifecycle taxonomy](https://cyclonedx.github.io/cyclonedx-property-taxonomy/cdx/lifecycle.html). The `offing:lifecycle` names are project-specific extension properties. They carry sets of values per component. A consumer should use the rule ID in the corresponding Ebb data to associate a specific source or replacement with that rule when multiple rules apply.

New CycloneDX external references use type `documentation` and carry the source title as their comment. A pre-existing reference with the same URL satisfies the source link. Existing properties and references are preserved. Offing skips a property with the same name and value if the input already contains it.

## SPDX

SPDX 2.3 JSON retains its package annotation and external reference structure. An annotation with `annotator: "Tool: offing"` and `annotationType: "OTHER"` has a comment of the form `offing:lifecycle:milestone:endOfLife:2026-01-01` or uses `endOfSupport`. Its `annotationDate` is midnight UTC on the milestone date. Evidence URLs appear in package `externalRefs`, with category `OTHER` and type `documentation` for newly added references.

In compact SPDX 3.0.1 JSON-LD, each applicable rule generates a Core [Annotation](https://spdx.github.io/spdx-spec/v3.0.1/model/Core/Classes/Annotation/) whose `subject` is the SPDX identifier of a Software Package. Offing adds the annotations to the top-level graph. The annotation uses `annotationType: "other"`, `contentType: "application/json"` and `comment: "offing:lifecycle:v1"`. Its string-valued `statement` contains a JSON object with these fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `ruleId` | String | Ebb rule ID |
| `milestone` | String | `endOfLife` or `endOfSupport` |
| `date` | String | Ebb deadline, `YYYY-MM-DD` |
| `sources` | Array of HTTPS URL strings | Evidence links for this specific rule |
| `replacement` | Optional string | Ebb replacement text |

Evidence links also appear on the subject package as Core [ExternalRef](https://spdx.github.io/spdx-spec/v3.0.1/model/Core/Classes/ExternalRef/) locators. Newly added links use `externalRefType: "documentation"`. Offing assigns a stable annotation identifier from the subject and statement. The embedded creation timestamp uses the first cited source's recorded access date as the evidence snapshot date.

## Conformance

Run the profile checker with Node.js 22 or newer. It accepts a CycloneDX JSON file, an SPDX 2.3 JSON file or a compact SPDX 3.0.1 JSON-LD file. The checker validates profile fields and links without loading the original registry or fetching the context. A document with no profile records can pass with a count of zero. Validate the whole document separately against the format's official schema.

```sh
offing sbom enrich bom.json > enriched.json
node check.mjs enriched.json
```

[Download the standalone checker](https://velella.sh/offing/spec/lifecycle-properties/conformance/check.mjs).
