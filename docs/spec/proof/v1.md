# Offing migration proof v1

The [proof schema](https://velella.sh/offing/schemas/proof.v1.schema.json) defines
`offing.proof.v1` and references the existing
[verification](../verify/v1.md),
[test-run](https://velella.sh/offing/schemas/test-run.v1.schema.json), and
[agent-run](https://velella.sh/offing/schemas/agent-run.v1.schema.json) contracts.

| Field | Evidence |
| --- | --- |
| `outcome` | The producer's recorded `done` or `stopped` state. |
| `range` | The full, lowercase base and head Git commit IDs. Both are required even for stopped runs and must match the corresponding scan commit IDs. Equal endpoints are allowed and have zero changed paths. |
| `verify` | The complete verification result with the before and after identities, Offing and Ebb data versions when known, finding counts, verdict and recorded command statuses. |
| `testRuns` | Test runs in recording order, including retries, statuses, totals, failures and redacted log digests. Empty arrays mean there is no attached test evidence. |
| `agentRuns` | Agent results in recording order, including reported turns, usage and driver versions. Unknown turn or usage values stay null. |
| `diff` | Counts of added, changed and deleted paths between the two commit trees. Renames count as deletion and addition. Mode and object-type changes count as changed. |
| `budget` | Elapsed milliseconds and the recorded USD cost. A null cost means unreported. |
| `tools` | The producer's Offing and Git version strings. |

## Verify a bundle

Place the proof and log sidecars in one directory. Each referenced digest
`<sha256>` names `offing-log-<sha256>.txt` in that directory. It is the
SHA-256 of the exact published log bytes. Several evidence fields can reference
the same content-addressed sidecar. Reporters leave both embedded test
log tails empty. A verification command with `not-run` or `skipped` status
has a null exit code and digest. A passed command has exit code zero and
a digest. A failed command has a positive exit code and a digest.

```sh
offing proof verify offing-proof.json --repo /path/to/clone
```

The repository defaults to the working directory and must already
contain both commit objects. The verifier compares the two trees
directly without consulting the working tree, following replacement
objects, fetching missing objects or running recorded commands. It
checks the embedded schema, scan identities, finding counts, verdict,
command metadata, diff counts and every referenced log hash. Proofs
may be up to 8 MiB. Each sidecar may be up to 32 MiB. Inputs must be regular
files. The CLI exits with 0 for consistent evidence, 1 for contradictory
or missing evidence and 4 for an invalid proof document.

Verification confirms consistency with locally supplied evidence. The producer's
outcome, agent results, budget, tool versions, and scan observations are
recorded claims. Workflow identity and proof authenticity require a separate
attestation. See the [proof guide](../../PROOF.md) for a recorded evaluation
and a workflow-signature verification example.

## Pull request evidence

Use `prepareAutopilotProofPublication(run, evidence, logs, environment, secretEnv)` from
`@velella/offing/proof` to assemble evidence from a terminal `offing.autopilot-run.v1` record.
Supply the local `repo`, the paired scan comparison as `verify`, recorded `testRuns` and
`agentRuns`, and the recorded `budget` and `tools`. The checkout base must match the before
scan and be an ancestor of the after commit. The helper verifies those commits and uses
Git to compute the diff counts without fetching or running repository commands.

Link verification commands with `commandResults`, an array of `{ commandIndex, testRunIndex }`
entries. Match the planned command to its JSON argv, or its space-joined argv when the
arguments contain only letters, digits, and simple command-path punctuation. An explicit
null `testRunIndex` marks a skip. Unlinked commands stay not run. Completed attempts carry
the final attempt status and actual exit code, including zero when reports fail and null
when the process times out. A failed command still needs a log. Its digest covers the
published UTF-8 text `[stdout]\n` + stdout + `\n[stderr]\n` + stderr after redaction. The
recorded-run helper caps the combined size of unique source or published logs at 64 MiB.
A completed run needs passing verification and at least one linked passing test. A stopped
run can have no test results when execution stopped before testing.

Use `prepareProofPublication` from `@velella/offing/proof` with an evidence
document, a map of source log SHA-256 digests to full UTF-8 strings, the
environment and any additional environment variable names marked secret.
The helper applies the Autopilot guardrails secret filter to document strings
and logs before producing artifact contents or Markdown. It recalculates the
published digests from the redacted bytes and clears inline log tails. Save
the returned named files together to publish the proof. All JSON and sidecar
contents are UTF-8, with the proof file named `offing-proof.json`.

The Markdown shows outcome, turn counts, test runs and budget. The recorded-run
helper also includes counts for passed, failed, skipped, and not-run commands
before `<!-- offing-proof:v1 -->`. The marker precedes a fenced JSON block
when the complete fence fits in 48 KiB measured in UTF-8. Otherwise, the
machine section names `offing-proof.json` and supplies its SHA-256 digest.
Attach the JSON and the log sidecars together in either case.

## Independent checker

Run the distributed [checker](conformance/check.mjs) from any directory
using Node.js and Git. Its default schema directory is the installed
package's `schemas` directory. To copy it on its own, supply the four
published schemas and install Ajv 8 beside the script.

```sh
node check.mjs offing-proof.json /path/to/clone /path/to/schemas
```

The distributed [suite](conformance/suite.mjs) builds synthetic Git and
evidence fixtures in a fresh temporary directory and compares the two
verifiers on valid evidence, a tampered log, mismatched scan identities,
incorrect diff counts, and an invalid nested agent result. It also checks
the redacted output of the installed publication helper with both verifiers. It
also builds green and stopped publications from recorded runs against the fixture's
real Git commits and checks all four verification command statuses.

```sh
node path/to/conformance/suite.mjs /path/to/installed/offing
```
