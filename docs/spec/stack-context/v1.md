# Stack context v1

The document is an offline, bounded view of reviewed lifecycle evidence for a project. The JSON schema identifier is [stack-context.v1.schema.json](https://velella.sh/offing/schemas/stack-context.v1.schema.json).

The MCP tool `stack_context` accepts `repository_path`, which defaults to the server working directory. The JSON resource `offing://stack/context` uses the server working directory. A session-start hook places the same document in its host's context field when the local scan cache can be reused. Source API checks use reviewed symbol matchers for the observed Node.js and Python pins.

## Fields

- `schemaVersion` is `offing.stack-context.v1`. `asOf` is the UTC day used to compare announced dates. `dataDate` is the most recent review date reported by the scan, or null when absent.
- `components` holds observed literal runtime pins. Each entry lists its `component`, `inUse` version, evidence status, and announced end date, rule ID, and source when available. A pin without a dated match has status `no-data` and a null end date, even when the dataset names other release lines.
- Each component's `supportedVersions` shows reviewed, bounded release lines with future announced end dates and their rule and source. An empty list means this dataset supplied no qualifying lines.
- `avoid` contains observed APIs or dependencies with a reviewed replacement. Every row names a package URL or an API label, the evidence rule ID and URL, and the reviewed replacement. Each end date is announced or null.
- `status` is `known` when the report can supply a dated runtime rule, a supported release line, or an observed avoidance rule with a replacement. Otherwise it is `no-data`. Absence of evidence conveys no safety conclusion.
- `omitted` counts distinct ranked entries left out of the document, including when the first entry alone does not fit. The limit applies to the complete JSON with two-space indentation, estimated as one token per three UTF-16 code units rounded up. The fixed maximum is 1,000 estimated tokens.

Rank entries by descending evidence severity, then earliest dated end of life, then component, rule ID and in-use version. Keep the prefix that fits and preserve that ordering within each array. Repeated references to the same entry count once.

## Conformance

Run `node docs/spec/stack-context/conformance/check.mjs <document.json> [schema.json]`. The standalone checker uses Ajv 8 and can run outside the Offing checkout using the published JSON schema. The candidate package also supplies a consumer exercise for the MCP and session-start interfaces.
