# Agent Driver v1

A driver is a user-selected executable and arguments. The caller starts it in
the isolated worktree. Prompts and results use files so neither becomes shell
syntax. The driver may read the prompt and make only the listed edits. It
leaves edits uncommitted. Offing owns rescanning and the local commit.

## Environment

| Variable | Value |
| --- | --- |
| `OFFING_PROMPT_FILE` | Absolute path to the UTF-8 prompt. |
| `OFFING_WORKTREE` | Absolute path to the allowed checkout and subprocess working directory. |
| `OFFING_ALLOWED_PATHS` | JSON array of permitted paths relative to the checkout, with forward slashes. An empty array permits no edits. |
| `OFFING_TIMEOUT_SECONDS` | Positive integer deadline in seconds. The caller may enforce a more precise deadline. |
| `OFFING_RESULT_FILE` | Absolute path where the driver writes its result as UTF-8 JSON. |

The legacy migration environment also supplies `OFFING_MIGRATION_PROMPT_FILE`
as an alias for `OFFING_PROMPT_FILE`. A legacy `migrate --agent` command can
continue to use its exit status alone.

## Results, scope and cancellation

Write one [`offing.agent-run.v1` result](https://velella.sh/offing/schemas/agent-run.v1.schema.json)
with the driver name and version, status, summary, relative paths touched,
turns and usage. Use `null` for unavailable driver version, turns, input or
output token counts, or USD cost. Values come from reported metrics.
Stable statuses are `completed`, `failed`, `blocked` and `timed-out`.
A completed run exits 0. A failed or blocked run exits nonzero and records
its status. A watchdog can terminate the process tree at the deadline and
produce a `timed-out` result when the driver cannot finish writing one.

The allowlist describes the intended edits. A trusted command runs with its
own OS permissions and credentials. The built-in agents use their available
permission controls, and Offing checks the final worktree diff. Drivers
should stop on cancellation, refrain from launching detached work, and
leave any edits in the isolated checkout. Use OS isolation when executing a
command whose behavior you do not trust. The conformance sentinel detects
changes to a specific outside path.

## Conformance

Download the [standalone checker](https://velella.sh/offing/spec/agent-driver/conformance/check.mjs)
and [reference driver](https://velella.sh/offing/spec/agent-driver/example/driver.mjs).
Run the following in their directory on Node.js 22 or newer.

```sh
node check.mjs node driver.mjs
```

The checker creates temporary worktrees and checks a fixed edit, an
out-of-scope write trap and a forced timeout. A passing run prints
`acc-agent-drivers`. The reference uses a deterministic local edit and
requires no account or model.
